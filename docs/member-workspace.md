# RR-016.4 — Member dashboard and research library

Implemented in the isolated member Worker, disabled by default through MEMBER_WORKSPACE_ENABLED=false. Apply migrations 0001–0005 to the member staging database before enabling. Configure the actual public HTTPS origin using PUBLIC_SITE_ORIGIN. Authentication is still through the separate member provider, with no staff permissions. No real accounts, data, pricing, or premium publications are created here.

Routes: /account (dashboard), /account/profile (optional display name and self-described professional category), /account/library (bookmarks, named collections and catalogue), /account/collections/:id (add from bookmarks, remove, rename, delete with confirmation), /account/membership (effective access and recorded expiry), /account/research/:key (private premium Markdown). Logout uses existing session invalidation. All account mutations require same-origin POST, a valid active session at write time, fixed field sets and server-derived member ID. A user cannot choose another account, staff role or entitlement. Collection operations also check ownership, including composite foreign keys. Limits: 500 bookmarks, 50 collections, 100 items per collection; first 100 catalogue records shown. Duplicate or over-limit additions are idempotent no-ops in this initial interface. No tracking of reading history, downloads, professional verification or private notes. Account export/deletion and full privacy/cancellation controls still required.

Only trusted publishing processes may populate member_content_catalog and member_premium_content; catalogue starts empty and no ingestion or admin publishing endpoint is exposed. Public links must use the configured origin and safe relative paths. Do not put premium full text into public Astro builds, Git history or search/RSS. Premium content is selected by a single query that requires published status, premium classification, active session/member and active, non-revoked entitlement. The response is private/no-store; never cache at the edge. Metadata can be visible to signed-in free members. Actual entitlement creation is reserved for trusted billing or controlled staging fixtures, not the reader interface. No checkout, subscription plans, renewal, charges, billing history or cancellation yet.

Tests run with a SQLite D1-shaped test double and synthetic sessions/entitlements, not real Cloudflare resources. Test authenticated staging with actual D1, provider recovery, cross-account and cache behavior, rate limiting and privacy before enabling public signup. Staff and member database instances remain separate. No local CMS changes; no public navigation links until confirmed account host and live deployment. No automatic import of public or private drafts.
