# RR-015H.2 — Local visual editorial CMS

From the repository root, run npm install and npm run editorial:cms. Open http://127.0.0.1:4317/ in your browser. Stop the server with Ctrl+C. Optional port: npm run editorial:cms -- 4318. The server binds only to 127.0.0.1, checks Host and Origin, requires a per-process session token for its JSON API, and does not expose repository files through arbitrary URL routes. Do not forward the port, proxy to the internet or share the session. It is a single-user local tool, not a remote or multi-user authenticated CMS.

The queue supports search, type and status filters, selecting visible drafts, and bulk creation of empty review records. Existing records are skipped, not approved. Select a record to edit Markdown/YAML or statutory JSON, preview Markdown with raw HTML and images disabled, or edit the actual human reviewer, date, summary, per-check and per-source attestations. Published content and structural templates are read-only. Saving a changed draft makes its prior review stale; explicitly archive stale reviews to reset checks. File hashes and review-record hashes detect stale client edits. The controls cannot authenticate evidence or verify identity; the human reviewer is accountable.

Statutory acquisition: put an authenticated PDF's extracted UTF-8 text and manifest.json under .rr-sources/<act>/ using the existing importer template and instructions. The CMS lists those manifests and invokes the draft-only importer. In a local import, Compare extracted text displays the original line selection and current version side by side, checking the manifest and extracted-source hashes against the import report. It is not a PDF visual diff or official-document verification; missing or changed local sources prevent a reliable comparison. No scraping or remote retrieval is added. Keep private materials outside public GitHub.

Relationships: existing references and acquisition-map candidates are displayed. Add or remove statutory links to reviewed published Acts/provisions and internal judicial treatments to earlier published judgments. A legal reviewer must verify each relationship and pinpoint. External judgment treatments can still be edited in Markdown front matter. If targets have not yet been published, the selectors remain unavailable. The existing Astro build remains the final authority for schema and references.

Publication: after explicit approval, choose the real publication date and Prepare candidate. The CMS writes a candidate in .rr-editorial/prepared (with a short reviewed draft hash in its filename), never changes the source draft flag, never commits, never deploys. Compare candidate with the current review and copy it manually to the appropriate content location, run npm run build and npm run test:publishing, inspect outputs and commit only after editorial approval. See editorial-review.md for the full review workflow and limitations. Local reviews and candidates are ignored by Git. Direct manual edits can bypass the CMS; no mandatory repository approval gate has been introduced.

Tests: npm run test:editorial now includes HTTP integration tests of origin/token protection, draft-only saves, stale review reset, bulk templates, incomplete approval, candidate generation and rejection of invalid targets and manifest paths. The tests are synthetic; they do not certify actual legal content or replace manual browser acceptance testing.
