# RR-015A — Content acquisition

## Primary sources
Use the official India Code portal (https://www.indiacode.nic.in/), Legislative Department (https://legislative.gov.in/) and official Gazette portal (https://egazette.gov.in/). Use the actual document-specific URL in every record, not a homepage. For judgments use official court sources. Authenticate state laws through the relevant state gazette/department. Do not scrape competing publishers or their editorial headnotes. Check reuse rights, reporting restrictions and privacy.

## Draft import
1. Download an authenticated source document and retain it locally under .rr-sources/ (ignored by Git). Extract UTF-8 plain text using a suitable PDF/HTML extraction tool, and compare against the official document. Scanned sources require manual transcription/OCR checking. The importer does not fetch or OCR PDFs.
2. Copy docs/templates/import/manifest.json to the source directory. The sample is synthetic. Specify source document URLs, capture dates, source text filenames, legal subject IDs, chapter labels, provision numbers and headings. For every version specify source ID, one-based inclusive startLine/endLine, and original source pinpoint (page or provision). Inspect line boundaries before importing. Exclude running headers, page numbers, and unrelated material only with documented editorial review. Preserve provisos, explanations, illustrations, schedules and footnotes where legally relevant.
3. Run npm run import:statute -- .rr-sources/<act>/manifest.json . Output is .rr-import/<slug>/draft.json and review.json, never public content. Source text is copied without paraphrasing (line endings normalized to LF; UTF-8 decoding may remove BOM). The report records source-text SHA-256 and selected text SHA-256, capture dates and line mappings; these hashes prove local file identity, not official authenticity. Keep original PDFs and their checksums separately.
4. Review each provision against the original source and current legal position. Verify dates and amendments independently; missing dates are not inferred. Review report flags non-listed source hosts. It is not an authentication service. Do not include private material in the public repository.
5. After editorial approval, copy the reviewed JSON into src/content/statutes/<slug>.json, fill genuine reviewer, reviewedAt and status, retain selected-provisions coverage unless completeness is verified, and set draft:false only after approval. Archive provenance separately; the importer does not publish, overwrite or certify. Run npm run build, npm run test:import and npm run test:publishing. Commit only verified public material. Amendments are separately sourced, and the editor must validate every relationship.

Start with selected provisions of MSMED and Arbitration rather than marking entire Acts complete. No actual statutory text has been imported or approved by this milestone.
