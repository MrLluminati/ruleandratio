# RR-016.3 — Online Editorial Studio (staging implementation)

The staff-only Worker now includes a private queue, draft creation and editing, rendered Markdown or statutory proof, source references, staff assignments, submission, evidence-based approval, blocked reviews, reopening and revision/review history. No publication endpoint, GitHub write token, public preview, member access or payment endpoint. The feature is disabled by default (STUDIO_ENABLED=false). Apply migrations 0003 and 0004 to the staff staging D1 database before enabling it. Cloudflare Access, active staff records, origin validation, HTTPS and the auth configuration from RR-016.2 are mandatory. Test on real staging before enabling for actual staff.

Create a document using the existing Markdown/YAML or statutory JSON draft format; require draft:true and no approval metadata. Paste extra issue text from the pilot inventory when importing an existing draft. This is manual import only, not bulk migration or automatic import of local approvals. The default review plan is generated server-side; extra checks are fixed at creation for now. Every approval requires a named reviewer, summary, evidence for each check and each source, primary-source pinpoints and confirmation. Owner self-review needs explicit acknowledgement; other staff cannot approve a revision they authored. All edits return the document to draft; approved documents must be reopened with a reason. Reopening preserves the historical review record but removes approved status. The online proof approximates the article text, not the public Astro rendering. No automated legal verification or complete Astro schema validation is claimed. Revalidation against the full publishing schema, pilot plan, exact hash, current approved state and legal review is mandatory in a future publication pipeline.

Authorization is evaluated from verified server identity and assignments. Mutations use a transactional D1 batch with a CHECK guard rechecking active staff role, document status, revision and plan hash, and assignment at write time; changes and audit event commit together or fail. No public signup for staff. Administrator assignment controls assign/revoke a pre-provisioned active author/reviewer; staff role provisioning remains out of band. Queue limits 200, history limits 20 revisions/10 reviews, no pagination or historical restoration yet. Draft data is stored in private D1; raw uploaded source files/PDFs remain outside this phase. Keep private data out of the public Git repository. Review evidence is recorded in D1, not a public artifact.

Synthetic tests use SQLite with a D1-shaped transactional test double, not actual D1 or Cloudflare Access. Real deployed authentication, D1 batch semantics, race/disablement testing, permissions, audit retention, rate limiting and browser testing are required before production. No Worker/database/account was deployed or configured by this commit.

The document generation counter increments on state changes, assignments and edits, preventing an old form from succeeding after a reopen/resubmit cycle with identical text and plan. Self-review checks both revision author and last editor. Do not treat any historical approval as current; publication must later identify the current approved review and generation.
